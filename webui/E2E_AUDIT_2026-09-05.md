## Confirmed user-facing issues

### J-lens steering controls become inaccessible

At 1280 × 720, adding a prediction direction leaves its operation controls clipped below the visible area. Clicking `ablate` repeatedly hits the section header or add-word form instead. This reproduced in the full run and the isolated rerun.

- Regression: `e2e/hosted.spec.ts:1221`, failure at line 1252.
- Relevant layout: `src/panels/JLensPanel.svelte:400` onward. The panel hides overflow, its steering section is capped at 50% height, and only a nested card region scrolls.

## Failures requiring test maintenance or further investigation

The 55 failed tests do **not** represent 55 confirmed product bugs. Reviewed traces include:

- Outdated copy and selectors: removed storage text, renamed inline chat actions, removed token provenance tooltips, and ambiguous `Chat`/`Conversation` selectors after the third controls tab was added.
- Outdated Loom assumptions: pointer-reactive background, node counts before shared-prefix segmentation, and required internal scrolling after cards were changed to fit all tokens.
- Numeric/text assertions: insignificant floating-point differences in pan coordinates; rolling-number DOM text includes both visual and accessibility representations.
- Several WebKit component tests fail while dynamically importing test modules. These do not establish a failure in the built application, but leave coverage gaps.
- Additional unresolved results: `Transition was skipped` errors during navigation/tab transfers, retained session data after model deletion, offline-notice positioning, a dark-theme gallery timeout, and 14 px versus expected 16 px landing padding. These have not been isolated sufficiently to label them all product defects.

The UI-polish review used rendered screenshots and actual click reachability, rather than treating every stale visual assertion as a defect. Light/dark backup-card checks and the newer backup export/import round-trip passed in the full suite. The backup test verifies a separate imported record, intact original record, integrity rejection, complete Loom restoration, and independent continuation of the imported copy.

Runtime failures:

- `faithful-readouts.test.mjs:172`: SSR of the SAE tab renders initial layer `-1` before its client-only effect selects layer 0, so the pinned probe assertion fails. This needs an appropriate client-render check or SSR-state repair; it is not evidence of incorrect activation arithmetic.
- `drowse-web-llm-backend.test.mjs:581`: source metadata now includes two additional undefined keys (`model_layers`, `description_source`), failing strict object equality.
- `instrument-availability.test.mjs`: failed without assertion output; an isolated rerun exited 139. The same check had passed in an earlier attempt this turn. Native process instability remains unresolved.
- `conversation-library.test.mjs`: printed `conversation library tests passed`, then failed to exit within two minutes. Its identified subprocess required termination. Assertions passed, but the command did not complete cleanly.
- `hosted-tools.test.mjs:41`: its multiline-only `createServer` call matcher misses the one-line call in `tab-identity.test.mjs:6`. That call does set `watch: null`; the checker reports a false unused-import failure and prevents later checks in the chain from running.
