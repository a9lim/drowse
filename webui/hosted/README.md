# Hosted Drowse shell

This Vite root is isolated from the dashboard bundled by `drowse serve`.

```bash
npm ci
npm run check:hosted
npm run test:hosted
npm run preview:hosted
```

Cloudflare Pages preview projects use `webui/` as the project root, `npm ci &&
npm run build:hosted` as the build command, and `dist-hosted` as the output
directory. The root `wrangler.jsonc` carries the equivalent static Pages
configuration.

`public-hosted/_headers` deliberately sends `X-Robots-Tag: noindex, nofollow`
while the hosted runtime remains an access-controlled feasibility preview.
The production project must use `npm ci && npm run build:hosted:release`. That
command fails unless the runtime, distribution, and model backend are verified,
then removes the preview-only noindex policy from the generated output. Source
preview files remain fail-closed.

The generated service worker precaches the shell only. Model weights and
instrument packs belong in verified OPFS storage and must never be added to
Workbox runtime caching.

## Search and agent discovery

The production homepage is prerendered from the original landing component at
build time. Its existing content becomes readable before JavaScript without
adding visible sections, navigation, footer links, or HTML guides. The
homepage remains the indexable URL in the release sitemap.
`DROWSE_PUBLIC_ORIGIN=https://drowse.ai` supplies canonical URLs, structured
data, sitemap links, and agent-resource URLs. Preview builds retain their
blocking robots file and response headers, including on Markdown.

`scripts/site-content.mjs` supplies direct machine-readable Markdown
documentation. The output also includes `llms.txt`, `llms-full.txt`, and a
draft Agent Skills discovery index with a SHA-256 digest of the operating
skill generated by `scripts/agent-discovery.mjs`. These resources document
actual product capabilities and the existing WebMCP integration; no remote
MCP or public inference server is introduced. They are not linked from normal
homepage content or navigation and use `noindex, follow` in release output.
They remain public and readable by anyone requesting their URLs; noindex is
an indexing instruction, not access control.

Nonvisual discovery metadata and HTTP Link relations expose the machine
resources. Cloudflare Pages uses the generated `_worker.js` on the routes in
`_routes.json` to negotiate `Accept: text/markdown`, preserve response headers,
and set `Vary: Accept`. Representation selection does not depend on user-agent
identity. Do not introduce crawler-only keyword text or hide promotional copy
in the landing page. See [Google's hidden-text and cloaking policies](https://developers.google.com/search/docs/essentials/spam-policies).

Other requests use static Pages delivery. The contact worker remains separate.
The app, contact, and credits rewrites use `app-shell.html`; the service
worker's navigation fallback is restricted to those routes. Machine resources
and missing URLs retain their own responses. Deploy both generated worker
files with the static output.

Run `npm run test:metadata` for landing, schema, machine-resource indexing,
skill-integrity, and negotiation contracts. Check that the original landing
interface remains unchanged and no HTML guide routes are emitted. After a
release, run:

```bash
npm run verify:site-discovery -- https://drowse.ai
```

For local Pages verification, build with a public origin, serve the output with
`wrangler pages dev`, and append `--preview` to the verification command.
The dated findings and indexing follow-up are in `docs/GEO-AUDIT-REPORT.md`.

The hosted application consumes compatible precomputed SAE and J-lens packs
on the GPU for steering, probes, gates, live readout, and token replay. It does
not train SAEs or fit J-lenses. Those authoring workflows remain available only
through the Python runtime; the browser worker rejects either request even if a
client constructs one manually. Browser manifold and template fitting is a
separate supported workflow and does not modify an installed SAE or J-lens.
